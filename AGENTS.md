# Инструкции для AI-агентов

Этот файл читают Claude Code, Codex и другие агенты. Правила здесь общие для всех.

## Что это за проект

Lab Bug Reporter: свой сервис баг-репортов для сайтов лаборатории. Сайт подключает SDK, пользователь через
кнопку «Get help» отправляет описание, скриншот или запись экрана, SDK прикладывает console, network и окружение.
Команда разбирает отчёты в dashboard.

Сначала прочитайте:

- [README.md](README.md): что это и как запустить;
- [docs/architecture.md](docs/architecture.md): как устроено, данные, API, структура папок;
- [docs/roadmap.md](docs/roadmap.md): что готово и что осталось.

Полное ТЗ лежит в `Lab_Bug_Reporter_Self_Hosted.pdf` в корне. Файл в `.gitignore`, в свежем клоне его может не быть.
Важные требования из него собраны ниже и в `docs/`.

## Стек

| Часть | Папка | Технологии |
|---|---|---|
| Сервер | `server/` | Java 21, Spring Boot 4.1, Spring Data JPA, Flyway, PostgreSQL 16, AWS SDK v2 |
| SDK | `sdk/` | TypeScript без фреймворков, Vite, сборка в один `dist/sdk.js` (IIFE) |
| Dashboard | `dashboard/` | React 19, TypeScript, Vite |
| Инфраструктура | `docker-compose.yaml`, `infra/` | Postgres, SeaweedFS (S3), Keycloak |

В Spring Boot 4 используется Jackson 3: импорты `tools.jackson.*`, а аннотации по-прежнему
`com.fasterxml.jackson.annotation.*`. Тестовые аннотации лежат в новых пакетах, например
`org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest`.

## Команды

```bash
docker compose up -d                 # Postgres, SeaweedFS, Keycloak

cd server && mvn test                # нужен запущенный Docker: Testcontainers сам поднимает Postgres и SeaweedFS
cd sdk && npm run build              # npm run dev только пересобирает файл при изменениях
cd dashboard && npm run dev          # http://localhost:3000
```

Сервер читает корневой `.env` сам. Значения из `.env` нельзя выводить в логи, ответы и коммиты.

## Правила кода

- Сначала прочитайте соседний код и пишите так же. В Java отступы табами, Lombok, DTO как `record`.
- Слои: контроллер (только HTTP) → сервис (логика) → репозиторий (данные). Сущности не отдаются через API.
- Код организован по фичам: `ingest`, `report`, `project`, `storage`, `security`, `user`, `exception`, `config`.
- Понятные английские имена, без сокращений вроде `uid`. Одна сущность называется одинаково во всех слоях.
- Комментарии объясняют «почему», а не «что».
- Новая логика идёт вместе с тестом рядом.
- Все ошибки API в одном формате `{ status, error, message }`, см. `GlobalExceptionHandler`.
- Время создания и изменения заполняет JPA Auditing (`@CreatedDate`, `AuditingEntityListener`), а не ручной `now()`.
- Схема базы меняется только миграциями Flyway. Применённую миграцию не редактируют, добавляют новую.
- Списки отдаются с пагинацией. Пути API версионируются: `/api/v1/...`.
- Во фронтенде загрузка показывается skeleton-анимацией. У каждого экрана с данными есть loading, empty и error.

## Требования ТЗ, которые нельзя нарушать

- Ничего не уходит с браузера до нажатия Submit.
- SDK никогда не ломает страницу сайта: обёртки `fetch` и XHR ведут себя как оригиналы, ошибки SDK не всплывают наружу.
- Собственная отправка SDK не попадает в network-лог.
- Маскируются только значения `Authorization`, `Cookie` и `Set-Cookie`. Это единственное правило маскировки.
- Захваченные данные показываются как текст, никогда как HTML.
- Тела отчётов не пишутся в логи сервера.
- Скриншоты, видео и контекст хранятся только в S3, не на диске контейнера и не в базе.
- Проекты задаются файлом конфигурации, а не базой. `ProjectRegistry` читает его при старте.
- Отчёт из проекта, недоступного пользователю, отдаёт 404, а не 403. Недостаточная роль отдаёт 403.
- Не входит в v1: расширение браузера, транскодирование видео, исполнители, комментарии, уведомления,
  rate limiting, очистка данных, админка, AI-функции. Поддерживается только Chrome.

## Git

- `main` и `develop` напрямую не меняются. Работа идёт в `feat/*`, `fix/*`, `docs/*`, стабильное сливается в `develop`.
- Маленькие коммиты в формате Conventional Commits на английском: `feat(back): ...`, `fix(sdk): ...`, `docs: ...`.
- Коммиты и PR не содержат упоминаний AI: никаких `Co-Authored-By` и «Generated with».
- Не коммитьте `.env`, секреты и PDF с ТЗ.
- Без явной просьбы владельца нельзя делать push, merge, force-push и удаление веток, а также создавать PR и issue.
- Папка `sdk/` ведётся другим разработчиком. Изменения контракта в ней нужно отдельно упомянуть.
- Рабочие настройки деплоя и окружения не меняются без запроса, если они не сломаны.
